# jitsi2outline

Автономный сервис для приватной локальной записи звонков **Jitsi Meet**, транскрипции на **CPU** и сохранения результатов в базу знаний **Outline** с интеграцией в **Zulip**.

---

## 🎯 Цели и контекст проекта

1. **Контекст звонков:** Видеозвонки Jitsi запускаются из мессенджера **Zulip** (кликом по кнопке звонка, генерирующей ссылку на комнату `meet.jit.si/<room>`).
2. **On-demand подключение:** Бот должен подключаться к звонку не постоянно, а по запросу участников (по команде/уведомлению из Zulip или вебхуку).
3. **100% On-Premise / Приватность:** Аудиоданные не должны уходить в сторонние облака (Recall.ai, Otter, Fireflies и т.д.). Вся обработка происходит строго в локальном контуре.
4. **Транскрипция на CPU:** Обработка аудио выполняется локально на CPU (скорость не критична, приоритет — качество и надежность).
5. **Интеграция с Outline:** Результаты транскрипции оформляются в Markdown и автоматически публикуются в базу знаний **Outline** через REST API.
6. **Обратная связь в Zulip:** Ссылка на готовый документ в Outline отправляется обратно в ту же тему (stream/topic) в Zulip.

## 🔬 Результаты исследования компонентов

### 1. Подключение и запись аудио из Jitsi
* **Почему не Jitsi Jibri:** Jibri жестко завязан на внутренний протокол управления XMPP своего собственного сервера Jitsi. Для подключения гостем к публичному `meet.jit.si` он непригоден и избыточно тяжел.
* **Выбранный подход: Headless Chromium + `puppeteer-stream` (Node.js)**
  * Позволяет захватывать входящий аудиопоток страницы напрямую через Chrome DevTools / Extension API без необходимости поднимать тяжелые виртуальные дисплеи (Xvfb) и виртуальные аудиосерверы (PulseAudio).
  * **Автоматический вход без кликов по интерфейсу:** Настройки Jitsi передаются прямо в хеш URL:
    ```text
    https://meet.jit.si/<ROOM_ID>#config.prejoinConfig.enabled=false&config.startWithAudioMuted=true&config.startWithVideoMuted=true&userInfo.displayName="🎙️ Transcriber"
    ```
    Это отключает экран пре-джойна (Lobby) и выключает микрофон/камеру бота, избавляя от зависимости от изменений UI Jitsi.
  * **Определение конца встречи:** Скрипт отслеживает количество участников через селекторы DOM или Jitsi API. Если в комнате остался только бот (или по таймауту тишины / команде стоп), запись финализируется.

### 2. Локальная транскрипция на CPU
* **Движок:** [`faster-whisper`](https://github.com/SYSTRAN/faster-whisper) (на базе CTranslate2).
* **Конфигурация для CPU:**
  * `device="cpu"`
  * `compute_type="int8"` — уменьшает потребление памяти и ускоряет инференс на CPU в 2–4 раза без потери качества.
  * Модель: `large-v3` для максимального качества русского и английского языков (или `medium` для более быстрой работы).
* **Форматирование:** Скрипт разбивает аудио на сегменты с таймкодами:
  ```markdown
  [00:05] Всем привет, давайте начнем обсуждение архитектуры...
  [00:18] По второму пункту предлагаю следующее решение...
  ```

### 3. Экспорт в Outline
* Outline предоставляет простой REST API.
* Эндпоинт: `POST /api/documents.create`
* Авторизация: `Authorization: Bearer <OUTLINE_API_KEY>`
* Полезная нагрузка:
  ```json
  {
    "collectionId": "<COLLECTION_ID>",
    "title": "Встреча: <Название темы из Zulip> (<Дата>)",
    "text": "# Транскрипт встречи\n\n**Дата:** 2026-09-13\n**Тема Zulip:** ...\n\n---\n\n## Расшифровка\n...",
    "publish": true
  }
  ```
* Ответ API возвращает `data.url` (или путь к документу), который формирует ссылку для отправки в Zulip.

### 4. Интеграция с Zulip и автоматическое подключение бота

#### Сценарий активации: Ненавязчивый полуавтомат через эмодзи-реакции
Чтобы не засорять чаты лишними служебными сообщениями и не записывать случайные короткие созвоны, принята следующая механика:

1. **Детект звонка:**
   * Zulip-бот подписан на поток событий (Events API).
   * Когда кто-то запускает видеозвонок, Zulip отправляет системное сообщение с ссылкой на `meet.jit.si/...`.
   * Бот перехватывает это сообщение, извлекает URL комнаты и ID сообщения.
2. **Тихое предложение записи (без спама в чат):**
   * Бот **не пишет текстовых сообщений в тему**.
   * Вместо этого бот сразу **ставит эмодзи-реакцию `🎙️` (или `🔴`)** на само сообщение о начале звонка через Zulip API (`POST /messages/{message_id}/reactions`).
3. **Подключение по клику:**
   * Если кому-то из участников нужен транскрипт встречи, он просто кликает по уже поставленной реакции `🎙️` (или добавляет её).
   * Бот отслеживает событие `reaction: add` для этого сообщения:
     * Запускает фоновый контейнер/процесс Puppeteer-рекордера с извлеченным URL.
     * Чтобы подтвердить старт записи, бот может добавить реакцию `🔴` к сообщению (визуальный индикатор записи без текста).
4. **Если реакцию никто не нажал:**
   * Бот ничего не делает, звонок не записывается, ресурсы сервера не тратятся.
5. **Завершение и публикация:**
   * Когда все участники выходят из Jitsi, рекордер завершает работу.
   * `faster-whisper` транскрибирует запись на CPU.
   * Документ создается в Outline.
   * Только после этого бот отправляет в тему Zulip итоговое сообщение со ссылкой на транскрипт:
     ```markdown
     🎙️ **Транскрипция встречи готова!**

     📄 Документ в Outline: [Открыть транскрипт](https://outline.your-domain.com/doc/...)

     <details>
     <summary>Краткое превью</summary>

     [00:00] ...
     </details>
     ```

## 📋 Задачи для агента-разработчика

1. **Этап 1: Recorder (`recorder/record.js`)**
   - Реализовать скрипт Puppeteer с `puppeteer-stream`.
   - Проверить заход по тестовой ссылке Jitsi с флагами URL (отключение prejoin, muted audio/video).
   - Запись аудиопотока в файл `audio.wav`.
   - Завершение записи по выходу участников или по внешнему сигналу.

2. **Этап 2: Transcriber (`transcriber/transcribe.py`)**
   - Настроить `faster-whisper` на CPU с `int8`.
   - Функция формирования Markdown-текста с таймкодами.

3. **Этап 3: Outline Client (`transcriber/outline_client.py`)**
   - Реализовать метод создания документа в Outline через REST API.
   - Обработка ошибок и получение публичной/внутренней ссылки.

4. **Этап 4: Zulip Bot & Pipeline (`transcriber/zulip_bot.py`)**
   - Реализовать обработку входящих сообщений: парсинг URL звонка Jitsi.
   - Запуск Puppeteer-контейнера/процесса.
   - Отправка финального сообщения с результатом в ветку.

5. **Этап 5: Docker Compose**
   - Упаковать в единый `docker-compose.yml` для развертывания на локальном сервере.
